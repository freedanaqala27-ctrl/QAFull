# 前端文案与术语固定标准

## 适用范围
这份标准用于约束流程系统前端中的页面标题、副标题、按钮文案、表单标签、状态文本、日志文案和摘要卡片。

目标只有三个：
- 用户一眼看懂当前步骤在做什么。
- 页面语言尽量贴近操作者，而不是贴近脚本或论文内部术语。
- 同一类对象在全站始终使用同一种叫法。

## 1. 技术缩写的展示规则
### 1.1 需要保留括号的缩写
当缩写本身是业务中常用识别方式，且用户需要把中文概念与英文缩写建立稳定映射时，前端首次展示使用“中文全称（缩写）”。

固定写法：
- 卷积神经网络（CNN）
- 循环神经网络（RNN）
- Transformer 模型（Transformer）

适用场景：
- 下拉选项
- 对象详情
- 任务摘要
- 首次出现的筛选标签

### 1.2 不需要保留括号的情况
以下情况直接用中文，不额外保留英文或缩写：
- 优化训练
- 基础 / 中级 / 高级
- 代码补全 / 模型搭建 / 模型修订 / 训练分析

### 1.3 原始字段名的展示规则
如果页面是在说明导入文件字段、数据库列名或脚本输入要求，保留原始字段名，并使用代码样式展示，例如：
- `participant_id`
- `blind_exercise_id`
- `package_id`

这类字段名属于技术输入要求，不翻译成中文字段名后再回译。

## 2. 模型名与版本名的展示规则
### 2.1 永远不翻译的模型名
第三方模型名、供应商模型名、接口型号名保持原文，不做中文翻译。

当前固定保留原文的模型名：
- `qwen-plus`

前端展示句式统一为：
- 生成模型 qwen-plus

后续新增模型也遵循同一规则，例如 `gpt-4.1`、`deepseek-chat`、`glm-4` 这类名称都直接保留原文。

### 2.2 模板与版本名的展示方式
模板名、提示版本、流程版本不翻译其内部代号，但要补足中文语义。

固定写法：
- 模板版本 MP-v1

禁止直接写：
- MP-v1
- Prompt 版本 MP-v1

## 3. “编号”与“ID”的使用规则
### 3.1 前端用户可见标签优先使用“编号”
只要字段代表的是流程系统里供人识别、选择、审核或追踪的业务对象，前端统一使用“编号”，不用“ID”。

固定写法：
- 任务编号
- 候选编号
- 审核工单编号
- 参考题编号
- 批次编号
- 配对编号
- 题目编号

### 3.2 只有这些情况才保留“ID”
以下场景保留 `ID` 或原始字段名：
- 数据库字段名
- CSV 列名
- Manifest 字段
- API 参数名
- 调试信息或技术文档中的原始 schema

示例：
- `participant_id`
- `question_id`
- `response_id`
- `submission_id`

### 3.3 不允许混用的写法
以下写法在前端页面中应避免：
- 参考题 ID
- 来源任务 ID
- Pair ID
- Exercise ID

应分别改为：
- 参考题编号
- 来源任务编号
- 配对编号
- 题目编号

## 4. 页面文案风格规则
### 4.1 标题
- 只用中文
- 尽量短
- 直接说明页面承担的任务

示例：
- 工作台
- 生成控制
- 审核中心
- 问卷分发
- 数据导入
- 分析报告

### 4.2 副标题
副标题必须回答“这一步是做什么的”，不要复述脚本编号，也不要堆内部黑话。

推荐写法：
- 这一步用于导入问卷原始数据，并整理出后续生成分析报告所需的正式分析输入。

不推荐写法：
- 执行 17a 并刷新 manifest。

### 4.3 按钮文案
按钮文案统一使用动作导向表达，优先“动词 + 结果”。

推荐写法：
- 开始生成候选题
- 补齐评测资产
- 开始批量评测
- 生成本次问卷材料
- 开始导入并整理分析输入
- 一键生成完整报告
- 锁定当前发布快照

避免写法：
- 确定
- 提交
- 运行 17a
- 执行 06c

## 6. 实现约束
前端代码不要手写重复标签，优先复用统一 helper。

当前统一入口位于：
- `evaluation_system/state_store.py`

应优先复用的 helper：
- `topic_label(...)`
- `difficulty_label(...)`
- `exercise_type_label(...)`
- `prompt_version_label(...)`
- `model_label(...)`
- `identifier_label(...)`

新增页面或组件时，先查这份标准；如果出现新术语，先补标准，再进页面。
